## 一、权限设计总览

### 1.1 角色定义（所有合约均基于 OpenZeppelin AccessControl）

| 合约 | 角色 | 权限 | 初始授予 |
|------|------|------|----------|
| **KYCRegistry** | `DEFAULT_ADMIN_ROLE` | 管理所有角色（grantRole/revokeRole） | admin |
| | `KYC_ADMIN_ROLE` | 调用 `setKYCStatus` | admin |
| | `PAUSER_ROLE` | 调用 `pause/unpause` | admin |
| **AccessController** | `DEFAULT_ADMIN_ROLE` | 调用 `setKYCRegistry` | admin |
| | `PAUSER_ROLE` | 调用 `pause/unpause` | admin |
| **KYCGuardedToken** | `DEFAULT_ADMIN_ROLE` | 调用 `setAccessController` / `setLimitController` | admin |
| | `MINTER_ROLE` | 调用 `mint` | admin |
| | `PAUSER_ROLE` | 调用 `pause/unpause` | admin |
| **LimitController** | `DEFAULT_ADMIN_ROLE` | 调用 `setKYCRegistry` | admin |
| | `LIMIT_ADMIN_ROLE` | 调用 `setLevelLimits` | admin |
| | `PAUSER_ROLE` | 调用 `pause/unpause` | admin |
| | `CALLER_ROLE` | 调用 `checkAndUpdateOutflow`（由 KGT 持有） | 需手动授予 |

## 二、权限设计检查清单

### ✅ 2.1 基础安全（已满足）

- [x] **所有关键函数都有权限检查**：使用 `onlyRole(...)` modifier
- [x] **使用 OpenZeppelin 成熟库**：`AccessControl` / `Pausable` 均来自 OpenZeppelin
- [x] **零地址检查**：构造函数和关键函数都有 `require(addr != address(0))`
- [x] **紧急暂停机制**：所有合约都实现了 `pause/unpause`

### ⚠️ 2.2 权限分离（部分满足，有改进空间）

**当前状态**：
- ✅ 角色分离清晰：`KYC_ADMIN_ROLE` / `LIMIT_ADMIN_ROLE` / `MINTER_ROLE` 等职责明确
- ⚠️ **所有角色初始都授予同一个 admin 地址**：单点风险
- ⚠️ **DEFAULT_ADMIN_ROLE 权限过大**：可以 grant/revoke 任何角色，包括自己

**建议改进**（PoC 阶段可选，主网前必须）：
1. **多签治理**：将 `DEFAULT_ADMIN_ROLE` 授予多签钱包（如 Gnosis Safe）
2. **角色分离**：将 `KYC_ADMIN_ROLE` / `LIMIT_ADMIN_ROLE` / `MINTER_ROLE` 授予不同的运营地址
3. **Timelock**：关键操作（如 `setKYCRegistry` / `setAccessController`）通过 Timelock 延迟执行

---

### ⚠️ 2.3 升级与回滚机制（缺失）

**当前状态**：
- ❌ **所有合约都没有使用 Proxy 模式**：无法升级
- ❌ **没有 Timelock**：管理员可以立即执行任何操作
- ❌ **没有版本管理**：无法回滚到旧版本

**风险评估**：
- **PoC 阶段**：可接受（合约简单，风险可控）
- **主网前必须**：实现 Proxy + Timelock + 多签治理

**建议实现路径**（主网前）：
1. 使用 OpenZeppelin `TransparentUpgradeableProxy` 或 `UUPSUpgradeable`
2. 集成 OpenZeppelin `TimelockController`
3. 将 Proxy admin 授予 Timelock，Timelock 由多签控制

---

### ✅ 2.4 依赖关系检查（正常）

**依赖链**：
```
KYCGuardedToken
  ├─→ AccessController (可替换，通过 setAccessController)
  └─→ LimitController (可选，通过 setLimitController)

AccessController
  └─→ KYCRegistry (可替换，通过 setKYCRegistry)

LimitController
  └─→ KYCRegistry (可替换，通过 setKYCRegistry)
```

**检查结果**：
- ✅ 所有依赖都可以通过 `DEFAULT_ADMIN_ROLE` 替换（支持升级路径）
- ✅ 替换时都有事件 `KYCRegistryUpdated` / 零地址检查
- ⚠️ **没有 Timelock**：替换是即时的，存在风险

---

### ✅ 2.5 暂停机制（已实现）

**所有合约都支持紧急暂停**：
- `KYCRegistry.pause()` → 阻止所有 `setKYCStatus` 调用
- `AccessController.pause()` → 阻止所有 `canTransfer` / `canMint`（返回 false）
- `KYCGuardedToken.pause()` → 阻止所有 `_update`（mint/transfer）
- `LimitController.pause()` → 阻止所有 `checkAndUpdateOutflow`

**暂停权限**：
- 所有 `PAUSER_ROLE` 由 admin 持有（单点风险，但 PoC 阶段可接受）

**建议改进**（主网前）：
- `PAUSER_ROLE` 也应该授予多签或 Timelock

## 三、关键函数权限检查

### 3.1 KYCRegistry

| 函数 | 权限 | 检查结果 |
|------|------|----------|
| `setKYCStatus` | `onlyRole(KYC_ADMIN_ROLE)` + `whenNotPaused` | ✅ 正确 |
| `pause` | `onlyRole(PAUSER_ROLE)` | ✅ 正确 |
| `unpause` | `onlyRole(PAUSER_ROLE)` | ✅ 正确 |
| `grantRole` | `DEFAULT_ADMIN_ROLE`（继承自 AccessControl） | ✅ 正确 |

**潜在风险**：
- ⚠️ `DEFAULT_ADMIN_ROLE` 可以给自己授予 `KYC_ADMIN_ROLE`，然后随意修改任何用户的 KYC 状态
- **缓解措施**：主网前必须将 `DEFAULT_ADMIN_ROLE` 授予多签

---

### 3.2 AccessController

| 函数 | 权限 | 检查结果 |
|------|------|----------|
| `setKYCRegistry` | `onlyRole(DEFAULT_ADMIN_ROLE)` | ✅ 正确 |
| `canTransfer` | `public view`（无权限限制，只读） | ✅ 正确 |
| `canMint` | `public view`（无权限限制，只读） | ✅ 正确 |
| `pause` | `onlyRole(PAUSER_ROLE)` | ✅ 正确 |

**潜在风险**：
- ⚠️ `setKYCRegistry` 可以立即替换整个 KYC 注册表，如果替换成恶意合约，会导致所有转账被拒绝
- **缓解措施**：主网前必须通过 Timelock 延迟执行

---

### 3.3 KYCGuardedToken

| 函数 | 权限 | 检查结果 |
|------|------|----------|
| `mint` | `onlyRole(MINTER_ROLE)` | ✅ 正确 |
| `setAccessController` | `onlyRole(DEFAULT_ADMIN_ROLE)` | ✅ 正确 |
| `setLimitController` | `onlyRole(DEFAULT_ADMIN_ROLE)` | ✅ 正确 |
| `pause` | `onlyRole(PAUSER_ROLE)` | ✅ 正确 |
| `_update` | `internal`（由 `mint` / `transfer` 触发） | ✅ 正确 |

**权限检查链**：
1. `mint` → `onlyRole(MINTER_ROLE)` → `_update` → `accessController.canMint(to)`
2. `transfer` → `_update` → `accessController.canTransfer(from, to)` + `limitController.checkAndUpdateOutflow(...)`

**潜在风险**：
- ⚠️ `setAccessController` 可以立即替换访问控制器，如果替换成恶意合约，可能导致所有转账被拒绝或放行
- ⚠️ `setLimitController` 可以设置恶意限额控制器，导致所有转账被拒绝
- **缓解措施**：主网前必须通过 Timelock 延迟执行

---

### 3.4 LimitController

| 函数 | 权限 | 检查结果 |
|------|------|----------|
| `setLevelLimits` | `onlyRole(LIMIT_ADMIN_ROLE)` | ✅ 正确 |
| `setKYCRegistry` | `onlyRole(DEFAULT_ADMIN_ROLE)` | ✅ 正确 |
| `checkAndUpdateOutflow` | `onlyRole(CALLER_ROLE)` + `whenNotPaused` | ✅ 正确 |
| `pause` | `onlyRole(PAUSER_ROLE)` | ✅ 正确 |

**权限检查链**：
- `checkAndUpdateOutflow` 只能由持有 `CALLER_ROLE` 的地址调用（通常是 KGT 合约）
- KGT 在 `_update` 中调用 `limitController.checkAndUpdateOutflow(from, value)`

**潜在风险**：
- ⚠️ `setLevelLimits` 可以立即修改任何 level 的限额，可能导致用户突然无法转账
- ⚠️ `setKYCRegistry` 可以替换 KYC 注册表，如果替换成恶意合约，可能导致限额检查失效
- **缓解措施**：主网前必须通过 Timelock 延迟执行

## 四、关键安全风险总结

### 🔴 高风险（主网前必须修复）

1. **单点故障风险**
   - **问题**：所有 `DEFAULT_ADMIN_ROLE` / `PAUSER_ROLE` 都由同一个 admin 地址持有
   - **影响**：如果 admin 私钥泄露，攻击者可以暂停所有合约、修改 KYC 状态、替换依赖合约
   - **缓解措施**：主网前必须将关键角色授予多签钱包

2. **无升级机制**
   - **问题**：所有合约都没有使用 Proxy，无法升级
   - **影响**：如果发现 bug，无法修复，只能重新部署
   - **缓解措施**：主网前必须使用 Proxy + Timelock

3. **无 Timelock**
   - **问题**：所有关键操作（`setKYCRegistry` / `setAccessController` / `setLevelLimits`）都是即时生效
   - **影响**：如果 admin 被攻击，攻击者可以立即替换依赖合约，用户无法反应
   - **缓解措施**：主网前必须集成 Timelock（建议 24-48 小时延迟）

---

### 🟡 中风险（PoC 阶段可接受，主网前建议修复）

1. **角色分离不足**
   - **问题**：`KYC_ADMIN_ROLE` / `LIMIT_ADMIN_ROLE` / `MINTER_ROLE` 都由同一个 admin 持有
   - **影响**：运营风险集中
   - **缓解措施**：主网前将不同角色授予不同的运营地址

2. **无事件审计**
   - **问题**：部分关键操作（如 `grantRole` / `revokeRole`）依赖 OpenZeppelin 的默认事件，没有自定义事件
   - **影响**：审计追踪不够详细
   - **缓解措施**：主网前可以添加自定义事件（可选）

---

### 🟢 低风险（PoC 阶段可接受）

1. **无版本号**
   - **问题**：合约没有 `version()` 函数
   - **影响**：无法在链上查询合约版本
   - **缓解措施**：主网前可以添加（可选）

## 六、权限操作流程建议

### 6.1 当前 PoC 阶段流程

```
admin (单签)
  ├─→ 可以 pause/unpause 所有合约
  ├─→ 可以修改 KYC 状态（通过 KYC_ADMIN_ROLE）
  ├─→ 可以修改限额配置（通过 LIMIT_ADMIN_ROLE）
  ├─→ 可以 mint 代币（通过 MINTER_ROLE）
  └─→ 可以替换依赖合约（通过 DEFAULT_ADMIN_ROLE）
```

**操作记录建议**：
- 所有关键操作都应该在链下记录（谁、何时、为什么）
- 定期导出链上事件日志，与链下记录对比

---

### 6.2 主网阶段流程（目标）

```
多签钱包 (3/5 或 4/7)
  └─→ Timelock (24-48 小时延迟)
      ├─→ 可以 pause/unpause（紧急情况）
      ├─→ 可以替换依赖合约（需延迟）
      └─→ 可以管理角色（需延迟）

运营地址（分离）
  ├─→ KYC_ADMIN_ROLE → KYC 运营团队
  ├─→ LIMIT_ADMIN_ROLE → 风控团队
```
